# NovelKeeper 開発者向け手順書（ソースからビルドする人向け）

> ふだん使うだけの人は、このファイルを読む必要はありません。README.md を見てください。連携設定の初期値は設定済みなので、5章の作業は批評空間のページの作りが変わったときだけ必要です。

手持ちのノベルゲームを起動・管理し、**プレイ済の☑とクリア日を批評空間と連動**させるWindowsアプリです。

できること：

- 批評空間のデータベースをタイトルで検索して、作品を登録する（ブランド・発売日・中央値も自動で入る）
- 登録した作品をツールから起動し、プレイ時間を自動で計測する
- 未プレイ／プレイ中／プレイ済／中断で管理する
- プレイ済の☑とクリア日を批評空間に反映する（ツール → 批評空間）
- 批評空間で登録したプレイ済とクリア日を取り込む（批評空間 → ツール）

## 1. 用意するもの

| もの | 用途 | 入手方法 |
|---|---|---|
| Windows 10 / 11 | 実行環境 | － |
| Visual Studio Code | コードの編集 | インストール済み |
| .NET 10 SDK | ビルドと実行 | 下の手順 2 |
| VS Code 拡張「C# Dev Kit」 | C# の入力補完やエラー表示 | 下の手順 3 |
| 批評空間のアカウント | 書き込み・同期 | すでに持っているもの |

## 2. .NET 10 SDK をインストールする

1. スタートメニューで「ターミナル」（または PowerShell）を開きます。
2. 次のコマンドを実行します。
   ```
   winget install Microsoft.DotNet.SDK.10
   ```
   winget が使えない場合は、公式サイト（https://dotnet.microsoft.com/download/dotnet/10.0）から「SDK」の Windows x64 インストーラーをダウンロードして実行します。
3. ターミナルを**いったん閉じて開き直し**、次のコマンドでバージョンが表示されることを確認します。
   ```
   dotnet --version
   ```
   `10.0.xxx` と表示されれば成功です。

## 3. VS Code に拡張機能を入れる

1. VS Code の左側にある拡張機能アイコン（四角が4つのマーク）をクリックします。
2. 「C# Dev Kit」を検索してインストールします。「C#」拡張も一緒に入ります。

## 4. プロジェクトを開いて動かす

1. 受け取った zip を、分かりやすい場所に展開します（例：`D:\NovelKeeper`）。
2. VS Code で「ファイル → フォルダーを開く」から、`NovelKeeper` フォルダ（`NovelKeeper.csproj` があるフォルダ）を開きます。
3. 「表示 → ターミナル」でターミナルを開き、次のコマンドを実行します。
   ```
   dotnet run
   ```
   初回は必要なライブラリ（HtmlAgilityPack、SQLite など）が自動でダウンロードされます。
4. ランチャーの画面が表示されれば成功です。

> この時点では、まだ批評空間との連携設定をしていません。**検索は使えますが、書き込みと同期は使えません。** 次の「5」で設定します。

### ビルドでエラーが出たら
エラーメッセージ（`error CS....` を含む行）をそのままコピーして、Claude に貼ってください。

## 5. 批評空間の仕様を調べて、連携設定を書く（重要）

批評空間には公式APIがありません。そのため、フォームの項目名などをツールに覚えさせる必要があります。
初回起動時に、次の場所に設定ファイルが作られます。

```
%AppData%\NovelKeeper\egs_config.json
```

（エクスプローラーのアドレス欄に `%AppData%\NovelKeeper` と入力すると開けます。アプリの「連携設定ファイルを開く」ボタンでも開けます。）

`"TODO"` になっている項目を、以下の手順で調べて書き換えます。

### 5-1. 読み込み用の列名（PlayedColumn / ClearDateColumn）

1. ブラウザで批評空間の **SQL実行ページ**（`sql_for_erogamer_form.php`）を開きます。
2. 次のSQLを貼り付けて実行します。
   ```sql
   SELECT column_name, data_type FROM information_schema.columns
   WHERE table_name = 'userreview' ORDER BY ordinal_position;
   ```
3. 表示された列の一覧から、次の2つに当たる列を探します。
   - **プレイ済**を表す列（boolean 型であることが多いです）→ `PlayedColumn`
   - **クリア日・プレイ日**を表す列（date / timestamp 型）→ `ClearDateColumn`。なければ空欄 `""` にします。
4. 本当にその列で合っているかは、自分のIDで確かめます。
   ```sql
   SELECT game, uid, ＜候補の列名＞ FROM userreview WHERE uid = '自分のID' LIMIT 20;
   ```

### 5-2. ログインページ（LoginPage / LoggedInMarker）

1. 批評空間のログインページを開き、アドレスバーのURLを `LoginPage` に書きます。
2. ログインした後のページにだけ表示される文字（例：「ログアウト」）を `LoggedInMarker` に書きます。

### 5-3. 得点登録フォーム（ReviewFormUrl / PlayedField / クリア日の項目）

1. 批評空間にログインして、適当な作品の**得点・プレイ状況を登録するページ**を開きます。
2. アドレスバーのURLのうち、作品IDの部分を `{gameId}` に置き換えて `ReviewFormUrl` に書きます。
   例：`https://…/xxxx.php?game=12345` → `https://…/xxxx.php?game={gameId}`
3. **プレイ済のチェックボックス**の上で右クリック →「検証」を選びます（開発者ツールが開きます）。
4. 選択された `<input type="checkbox" name="○○○" …>` の `name` の値を `PlayedField` に書きます。
5. 同じようにして、**クリア日**の入力欄の `name` を調べます。
   - 入力欄が1つの場合（例：`2026-10-04` と入れる欄）→ `ClearDateField` に name を書き、`ClearDateFormat` に日付の形式（`yyyy-MM-dd` や `yyyy/MM/dd`）を書きます。
   - 年・月・日が別々の選択欄の場合 → `ClearDateYearField` / `ClearDateMonthField` / `ClearDateDayField` に、それぞれの name を書きます。

### 5-4. 文字コード（CharSet）

批評空間のページで右クリック →「ページのソースを表示」を選び、`<meta charset="…">` の値を確認します。`utf-8` 以外（例：`euc-jp`）なら `CharSet` を書き換えます。

### 設定例（値はあくまで例です。必ず自分で調べた値にしてください）

```json
{
  "BaseUrl": "https://erogamescape.dyndns.org/~ap2/ero/toukei_kaiseki/",
  "CharSet": "utf-8",
  "RequestIntervalMs": 2000,
  "SqlPage": "sql_for_erogamer_form.php",
  "SqlFieldName": "sql",
  "PlayedColumn": "（5-1で調べた列名）",
  "ClearDateColumn": "（5-1で調べた列名）",
  "LoginPage": "（5-2で調べたURL）",
  "LoggedInMarker": "ログアウト",
  "ReviewFormUrl": "（5-3で調べたURL。作品IDの部分は {gameId}）",
  "PlayedField": "（5-3で調べた name）",
  "PlayedValue": "",
  "ClearDateField": "（5-3で調べた name）",
  "ClearDateFormat": "yyyy-MM-dd",
  "ClearDateYearField": "",
  "ClearDateMonthField": "",
  "ClearDateDayField": "",
  "GamePageUrl": "game.php?game={gameId}"
}
```

保存したら、アプリを再起動します。

## 6. 動作確認の順番

一度に全部試さず、次の順に確認すると、問題の場所を切り分けやすくなります。

1. **検索**：「＋ 作品を追加」で検索し、結果が出るか確認します（SQLページの連携だけを使います）。
2. **起動と計測**：右側で実行ファイルを指定して保存し、「▶ 起動」を押します。ゲームを終了すると「プレイ時間を記録しました」と表示されます。
   - 起動してすぐ記録されてしまう場合は、起動用exeと本体exeが別になっています。タスクマネージャーの「詳細」タブで本体のexe名を確認し、「監視するプロセス名」に入れてください。
3. **ログイン**：「ログイン設定」でIDとパスワードを入れて、「ログインに成功しました」と出るか確認します。
4. **同期（読み込み）**：「⇅ 批評空間と同期」を押して、批評空間でプレイ済にしている作品が「批評空間」列に反映されるか確認します。
5. **反映（書き込み）**：**得点や感想を入れていない作品で**試します。☑プレイ済とクリア日を入れて「保存」を押し、批評空間のページで反映されたか確認します。
   - 問題なければ、得点や感想が入っている作品でも試し、**得点や感想が消えていないこと**を必ず確認してください。

### 批評空間のフォームの欄の名前が変わったとき

感想などの欄の name 属性は、`egs_config.json` の `ReviewFields`（項目名 → name）で変えられます。変えたい項目だけ書けば、ほかは既定値（`EgsConfig.DefaultReviewFields`）で動きます。項目名は `possession` `giveup` `total_play_time` `fun_time` `okazu` `purchase_will` `before_tokuten` `start_date` `platform` `operation` `platform_memo` `hitokoto` `sage` `memo` `netabare` です。プレイ済・クリア日・得点の欄は、従来どおり `PlayedField` `ClearDateField` `ScoreField` などで指定します（変更後はアプリの再起動が必要）。

### 仕組みのポイント

- **読み込み**：SQLページに SELECT 文を送り、返ってきたHTMLの表を `HtmlAgilityPack` で解析します（`EgsClient.QueryAsync`）。
- **書き込み**：得点登録ページを開いて、**フォームに入っている今の値をすべて読み取り**、プレイ済とクリア日だけを書き換えて送信します（`EgsClient.UpdateReviewAsync`）。こうすることで、得点や感想を上書きして消してしまうのを防ぎます。
- **確認**：送信した後、SQLページで読み直して反映されたかを確かめます。
- **失敗したとき**：エラーの内容を表示し、得点登録ページをブラウザで開いて手動で登録できるようにします。
- **プレイ時間**：起動したexe（または指定したプロセス名）のフォルダ内で動くプロセスを10秒ごとに監視し、1分ごとに途中経過を保存します（終了は2回続けて見つからなかったときに判定）。
- **応答の検証**：SQLページの応答に「SQLの実行結果」の見出しがなければ、メンテナンス・エラーのページとみなして例外にします（結果が0件のときは表が出ず、見出しだけが返ります）。「記録なし」と取り違えて、同期で全作品を未登録扱いにしないためです。
- **ログ**：握りつぶす例外も `Log.Warn` で `log.txt` に残します（512KBで1世代ローテーション）。

### 同期のルール

| 状況 | 動き |
|---|---|
| 批評空間でプレイ済、ツールで未プレイ | ツールをプレイ済にする |
| ツールでプレイ済、批評空間で未登録 | 確認してから批評空間に反映する |
| 両方にクリア日があり、日付が違う | どちらの日付を使うか確認ダイアログで選ぶ |
| ツールにクリア日がない | 批評空間の日付を取り込む |
| 得点・長文感想が両方にあり、内容が違う | 確認ダイアログで選ぶ（「以降も同じ選択」に☑すると、その同期の間は聞かない） |
| ツールで変更して未反映の項目 | 批評空間の内容で上書きしない（`PendingReview`） |
| 批評空間の記録が0件、かつ前回までは記録があった | 取得失敗の疑いとして、続けるか確認する |

規則は `SyncEngine.ApplyRecord` にまとまっており、`tests\NovelKeeper.Tests\SyncEngineTests.cs` で確認しています。

## 7.5 実行ファイルをまとめて設定する

### 自動検出
1. 上部の「🔍 実行ファイルを自動検出」を押します。
2. ゲームのフォルダ（初期値 `D:\novelgame`）と、「Steam でインストールしたゲームも探す」を確認して「検出開始」を押します。
3. 見つかったゲームと、名前が近い作品が並びます。作品の欄はクリックして選び直せます。
4. ☑ を確認して「☑ した作品に設定する」を押します。

- Steam のゲームは `steam://rungameid/〇〇` で Steam 経由で起動し、本体の exe を「監視プロセス」として設定します。
- 一致度 60% 以上で、まだ実行ファイルが未設定の作品には、最初から ☑ が付きます。
- 検出したフォルダの設定は `egs_config.json` の `GameFolders` / `ScanSteam` / `ShortcutFolders` / `ScanStartMenu` に保存されます。
- 起動する exe は「ショートカットのリンク先 ＞ ゲームエンジンの特徴（Unity・吉里吉里・Ren'Py）＞ 製品名・場所・大きさ」の順で選びます。候補が複数あるときは「使う exe」の欄で選び直せます。

### おすすめの手順
1. 自動検出で、exe を1つに特定できた作品（「exe」列が「✓ 特定」）をまとめて設定します。初期状態ではショートカットは使いません。
2. 一覧の「表示」で「起動設定が未設定」を選びます。
3. 残った作品の「起動設定」欄（黄色の「⬇ ここにドロップ」）に、デスクトップのショートカットをドラッグして設定します。

### ドラッグ＆ドロップ
exe、ショートカット（.lnk）、Steam のデスクトップショートカット（.url）を、一覧の作品の行にドラッグすると設定されます。詳細欄の「実行ファイル」の欄にドラッグすることもできます（その場合は「保存」を押して確定）。

## 7.6 自分の得点と並び替え

### 自分の得点
- 一覧の「得点」列に、自分の得点（0～100）が表示されます。
- 詳細欄の「自分の得点」に入力して「保存」すると、批評空間にも反映されます（「保存時に批評空間へ反映する」に☑のとき）。
- 得点だけを変えたときは、批評空間側のプレイ済の☑は変更しません。
- ツールで得点を空欄にして保存すると（確認ダイアログあり）、批評空間の得点も空にして反映します。批評空間は得点があるとプレイ済を外せないため、未プレイに戻すときに必要です。同期で自動的に消すことはありません（ツールで空欄にして保存したときだけ）。
- 「批評空間と同期」「一括取り込み」で、批評空間の得点を取り込みます。食い違うときはどちらを使うか確認します。
- 設定ファイルの `ScoreColumn`（初期値 `tokuten`）と `ScoreField`（初期値 `data[tokuten]`）を使います。

### 並び替え
- 上部の「⇅ 並び替え…」で、第3条件まで指定できます。
- 一覧の見出しをクリックしても並び替えられます。Shift を押しながら別の見出しをクリックすると条件を追加できます。
- 並び順は保存され、次回の起動時にも引き継がれます。
- 「並び替え設定1〜3」（`MainWindow.SortPresets.cs`）：並び替え画面のプルダウン（「設定*へ保存」）で保存し、ボタンで呼び出します。並び条件だけを `egs_config.json` の `SortPresets`（`List<List<SortKey>>`、`Normalize` で3件に整える）に持ち、絞り込みは含みません。設定ボタンの「×」で解除（確認あり）。幅が足りないときの ▼ メニューにも、「設定N」「設定Nを解除」が入ります。

## 7.7 プレイ時間の計測

- 10秒ごとに起動中のプロセスを調べ、**ゲームのフォルダの中にある exe** が動いていればプレイ中とみなします。ランチャーから本体が起動するゲームでも、「監視するプロセス名」の設定は通常不要です。
- ツール以外（デスクトップ、Steam）から起動しても計測します（ツールが起動・常駐している間）。
- 1分ごとに途中経過を保存します。スリープ中の時間は数えません。
- 「⚙ 設定」で次を選べます。
  - 操作していない時間を除外する（初期値：オン、15分）
  - ゲームの画面が前面にあるときだけ数える（初期値：オフ）
  - 閉じるボタンで常駐する（初期値：オン）
  - Windows の起動時に常駐した状態で自動起動する（初期値：オフ）
  - 計測の開始・終了を通知する（初期値：オン）
- 終了するときは、タスクバー右下のアイコンを右クリック →「終了」。
- 二重起動はできません（プレイ時間を二重に数えないため）。

## 7.8 一覧画面の配置（縦向きの画面にも対応）

- 一覧は、画面の幅が足りないと下に横スクロールバーが出ます（タイトル列は最低 240 ピクセルを確保）。
- 詳細欄は、見出し（⠿ 作品の詳細）をドラッグして移動できます。
  - 青い「右」「下」の場所で離す → 一覧の右（縦長）／下（横長）に固定
  - それ以外の場所で離す → 別ウィンドウになり、好きな位置・大きさで使える（Esc で取り消し）
  - 見出しの「⤓ 下へ / ⇥ 右へ / ⇥ 右に戻す」ボタンでも切り替えられます。
- 詳細欄は「✕」または上部の「詳細欄を隠す」で非表示にできます。再表示は上部の「詳細欄を表示」。
- 一覧と詳細欄の境目をドラッグすると大きさを変えられます。位置・大きさ・表示状態は保存されます。

## 7.9 起動するものを複数登録する（コンプリートボックスなど）

- 1つの作品に、起動するもの（exe・ショートカット・Steam・バッチなど、Windows で開けるファイル）をいくつでも登録できます。
- 詳細欄の「起動ファイル設定」の一覧で、追加（＋ 追加… またはファイルをドラッグ）、名前の変更（ダブルクリック）、並べ替え（↑↓）、削除ができます。
- ▶ が「今使うもの」です。一覧の「起動設定」列のプルダウン、または詳細欄の「▶ これを使う」で切り替えます。進み具合（1作目→2作目→FD など）に合わせて切り替えてください。
- 一覧の作品の行にファイルをドロップすると、そのファイルが追加され、今使うものになります（複数まとめてドロップ可）。
- プレイ時間は、登録したすべての起動するもののフォルダで判定するので、どれを起動しても記録されます。

## 8. 注意点

- 批評空間は個人運営のサイトです。このツールは操作したときにしか通信せず、通信の間隔は最低2秒あけています（`RequestIntervalMs`）。間隔は短くしないでください。
- 自動でフォームを送信することがサイトの利用ルールに反しないか、事前に確認してください。
- サイトの作りが変わると、書き込みは失敗します。その場合は手順5で設定を調べ直してください。
- データの保存場所は `%AppData%\NovelKeeper` です（`games.db`、`egs_config.json`、`credential.bin`）。バックアップするときはこのフォルダをコピーしてください（アプリ内では「データ出力」タブ →「バックアップ」。自動バックアップは `backups` フォルダに残ります）。

## 10. 仲間に配布する

1. `NovelKeeper.csproj` があるフォルダで `build.bat` をダブルクリックします。
2. 先にテストが走り、通ると数分で `dist` に次ができます。
   - `NovelKeeper_vX.Y.Z.zip`（通常版・約70MB。.NET 同梱）と `NovelKeeper_vX.Y.Z_lite.zip`（軽量版・約1MB。.NET 10 デスクトップ ランタイムが必要）。どちらの中身も `NovelKeeper.exe`、`使い方.txt`、`SHA256.txt`
   - `SHA256SUMS_vX.Y.Z.txt`（zip の SHA256。**zip とは別の場所**にも載せて渡すと、改ざんの確認に使えます。zip 内の `SHA256.txt` は破損の確認用です）
3. 通常版の zip を仲間に渡します。.NET のインストールは不要です。
4. コード署名をするときは、`build.bat` の前に `set SIGN_PFX=証明書.pfx` と `set SIGN_PASS=パスワード` を設定します。署名は `sign.ps1`（Windows 標準の PowerShell。Windows SDK の signtool は不要）が行い、`SIGN_PFX` が未設定なら署名しません。タイムスタンプは既定で DigiCert のサーバーを使います（`SIGN_TIMESTAMP` で変更、`none` で付けない）。自己署名の証明書でも署名は付きますが、Windows には「信頼されていない」と扱われ、SmartScreen の警告は消えません（警告を減らすには、認証局が発行した証明書が必要です）。

- `build.bat` を実行すると、前回のバージョン（`version.txt`）の最後の数字を1つ上げたバージョンを提案します。そのまま Enter で採用、別の番号にしたいときは入力します（例：`1.1.0`）。
- できた exe のバージョンは、画面のタイトルと、exe のプロパティ（詳細）で確認できます。
- アイコンの元データは `Assets\NovelKeeper.svg`、アプリに組み込むのは `Assets\NovelKeeper.ico` です。
- 配布向けの初期値（批評空間の連携設定）はコードに入っているので、仲間は「ログイン設定」をするだけで使えます。
- データの保存場所は `%AppData%\NovelKeeper` です（旧名 `ErogeLauncher` のフォルダは、初回起動時に自動で引き継ぎます）。
